# Advanced Customized Analytics (ACA)

ACA is an independent Worker and D1 service with a private local Studio dashboard. The production site remains static. Collection is default-off; configuring a public endpoint does not deploy or verify a service. No historical data is invented or backfilled.

Studio's Analytics destination is disabled while the saved **Enable ACA** setting is off. Direct Analytics bookmarks show a disabled state and a Configure ACA action without loading report/status requests or chart modules. Changing the saved setting closes an already-open dashboard and aborts its automatic status and report loads. Enabling ACA restores normal report access. This UI gate does not delete stored reports or change the independent collector service; deployment and diagnostic controls remain available in Advanced analytics settings.

## Deployment and credentials

Open **Studio → Site settings → Advanced analytics**. ACA now has a guided setup alongside its public collection settings:

1. Save the Cloudflare account and API token in Connections. Preserve existing Pages access and add D1 Edit and Workers Scripts Edit. A selected custom domain also needs Zone Read, DNS Edit and Workers Routes Edit. ACA has its own preflight and does not require Access permissions. The broader `services:check` command still checks Vinext prerequisites separately.
2. Choose a Worker name, D1 database name, service site ID and optional analytics hostname. The starter defaults to `glass-aca` and `analytics.example.com`; leaving the hostname empty uses the account's workers.dev subdomain. The allowed website is captured from the saved public site URL. Setup controls have their own private revision and participate in the normal Settings save/navigation flow.
3. **Check ACA connection** performs only read checks, showing scope failures without provisioning or claiming a deployment. Read access does not prove write access.
4. **Set up ACA** creates or reuses the named D1 database, applies all ordered migrations and prepares independent 256-bit private keys. It records resources before continuing so failed attempts can resume. Studio saves the generated report token privately in Connections. There is no manual database-ID editing or secret copy/paste. Existing unrelated Workers are rejected; connecting an existing ACA Worker requires its matching saved report token and preserves unknown network/deletion keys.
5. **Deploy ACA** includes setup when necessary, then uploads the independent Worker with its keys and chosen custom domain. The service enables event acceptance according to its Service controls; the website remains governed by its separate Enable ACA switch. Deployment verifies the exact site/origin/deployment ID, authenticated protocol-3 status and reports, rejection of unauthenticated status reads, and ingestion CORS. These checks do not send synthetic reader events. A failed post-upload check retains the unverified address.
6. A verified deployment fills the public Worker origin and site ID in the Settings draft. Review them, enable ACA, save, and **Build & Publish** the website when collection should begin. Reloading Studio retains the setup target, keys and last result; **Use this ACA service** restores the verified connection to a draft. Reports may initially be empty until real observations and maintenance have run.

The same managed flow is available as `npm run aca:deploy`. It uses the saved Studio credential and target, provisions/migrates as needed, and never publishes Pages or Vinext. A process lock serializes Studio and CLI deployments. Interrupted jobs retain their stopped phase and any uploaded address; inspect that service before another upload. No plan upgrades, database replacement, statistical-data deletion or automatic key rotation occur.

Private options live in `.studio/services/aca.json`; captured job metadata/logs, per-target keys and generated run configurations stay under `.studio/services/`. These are mode-restricted, excluded from notebook backups/public output and retained by notebook data reset. A temporary mode-0600 secrets file is supplied through Wrangler's additive `--secrets-file` option and removed after deployment. Only masked presence/status is returned to Studio. Missing existing keys are generated; retries preserve managed keys and existing remote keys that Studio cannot read. Never commit this directory.

The repository Wrangler file remains the local-development template, including its placeholder binding. Generated deployment configs resolve the real database, entry point, migration directory, domain and service variables privately. Local development still uses `npm run aca:migrate:local` and `npm run aca:dev`.

Service controls start at 1,000 accepted batches per UTC day, with 2,000,000 observed rows read and 60,000 rows written as service-local soft budgets. Account limits remain shared and these are not billing guarantees. Identity mode stays anonymous. Turn off Accept reader events and deploy to pause collection while preserving reports; the public site setting can also stop newly built readers from collecting.

The report token stays in private `.studio/connections.json` with write-only UI and revision checks, or the compatible `ACA_REPORT_TOKEN` server environment variable. It is forwarded server-to-server by the local Studio proxy, never by browser JavaScript. `IDENTITY_SECRET` remains a Worker secret and is not needed in Studio. Portable backups exclude both. Worker observability is disabled in the supplied config to avoid accidental request logging.

Private administrative reads and verification first use ordinary network resolution. On an explicit local DNS failure only, Studio can recover the configured HTTPS service through [Cloudflare's JSON DNS-over-HTTPS resolver](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/). Only the hostname is sent to the resolver; report paths, tokens, cookies and request data are excluded. Short TTL-bounded caching and shared pending lookups avoid repeated DNS work. The service request retains the original HTTPS hostname and normal certificate verification, refuses redirects, and bounds time/response size. Mutations are never retried through this recovery. This is private Studio transport; public reader collection keeps its normal browser networking and privacy/opt-out behavior. Unrecoverable connection failures return a translatable 503 with DNS/network guidance rather than an unexplained 400 `fetch failed`.

## Collection contract

`src/shared/aca.ts` defines compatible version 1 and version 2 batches and the public settings schema. A document gets a random view ID. Anonymous mode keeps it only in memory; it does not join visits across pages or sessions. Optional cross-day history is separately enabled and requires explicit reader opt-in in the privacy dialog at `/settings/#privacy`. The stable published content ID and revision accompany the view. Routes omit queries and fragments.

Batches carry a monotonically increasing sequence, cumulative active milliseconds, maximum geometric depth, twenty cumulative progress dwell buckets, heading dwell counters, end visibility and bounded discrete events with stable random IDs. D1 accepts newer cumulative state once; event primary keys deduplicate retries. Public requests require the configured Origin and site ID, JSON bodies under 32 KiB, at most thirty events per batch and five hundred retained discrete events per view. Payload schemas reject unknown fields. Views expire after 24 hours. No arbitrary SQL or arbitrary event names are accepted.

Reader updates run about every twenty seconds and on hide/page exit. Hidden tabs pause active time; sixty seconds without activity becomes idle. A five-second tick cap avoids counting long browser suspension as reading. Foreground time is an observation of an active document, not proof of attention. An impression requires at least half a card/result visible continuously for one second, once per item/surface in the document. Scroll jumps do not fill skipped reading buckets. Card clicks, outbound domains, file downloads, share/copy actions, image opens, widget actions, search result counts, supported Web Vitals and coarse runtime/promise failures are measured. Search terms, form inputs, error text and comment contents are excluded.

All reader batches use `fetch` with `credentials:'omit'`, including nonblocking `keepalive:true` updates on hide/page exit. JSON payloads are bounded by their UTF-8 byte length before sending. [Beacon's processing model](https://w3c.github.io/beacon/#processing-model) forces `sendBeacon` to use credentials, which conflicts with anonymous cross-origin collection; it is not used. The Worker permits only the configured site Origin and does not grant credentialed CORS. Acknowledged batches remove their delivered event IDs; later cumulative batches retain unacknowledged events. Offline shutdowns and the browser's keepalive quota can still lose a final update.

Attribution uses bounded referrer host, internal/direct category, sanitized `utm_source` and `utm_campaign`, viewport category and primary browser language. No IP address or fingerprint is stored. The worker necessarily receives network requests, but ACA does not persist their IP/headers. A service-wide native rate limiter bounds public ingestion to 600 requests/minute per Cloudflare location before D1 writes; choose an account-unique limiter namespace when configuring this service. Origin checks and bounded payloads limit misuse; a public endpoint cannot cryptographically prove a human visit. Use Cloudflare's service limits/WAF for sustained hostile traffic. The daily cap is an operational bound, not a precise billing quota under concurrent requests.

## Daily network estimates and legacy deletion

The current reader creates no persistent browser identity and offers no identity interface, banner, name field or account prompt. Existing opt-outs, DNT and GPC remain effective. With the author-level **Estimate daily networks** switch and the Worker mode both enabled, the service uses Cloudflare's connecting-address header only transiently. It does not accept IPs from event payloads, persist raw addresses or combine addresses with browser fingerprinting. Canonical IPv4/IPv6 forms share the same input; Cloudflare's synthetic cross-zone Worker address is excluded.

A site-specific HMAC includes the UTC day, so the same address has a different key on another day or site. Separate ephemeral keys deduplicate site, article and revision scopes in the ingestion transaction. Daily aggregate counters survive identifier removal. Keys logically expire by the following UTC noon (12–36 hours after observation), leaving cleanup headroom inside the 48-hour retention target. Five-minute bounded cleanup also runs when summary processing is paused; provider outages or exhausted account quotas can delay physical removal. Recovery resumes expiry first. No endpoint returns these keys.

Report series use **Estimated daily networks**. Longer-range cards show the average of days with network observations, never a sum labeled unique visitors. Missing observations remain unavailable. Shared addresses merge different readers; changing addresses can split one reader. These metrics cannot identify people or provide cross-day histories, returning-reader rates or cohorts. Separate consented browser cohorts can coexist with daily network estimates when optional history is enabled; daily network estimates themselves never provide those histories.

`IDENTITY_MODE=anonymous` is the safe default and discards identity supplied by stale clients. The explicit `optional-consent` mode accepts identities only after reader opt-in. `legacy-opt-in` remains compatibility/testing support. The `/v1/forget` endpoint remains available for old identities, including with browser privacy headers. It HMAC-hashes the presented legacy ID, deletes retained linkable raw state, and retains a revocation tombstone against late batches. Irreversible anonymous summaries remain. The privacy dialog at `/settings/#privacy` provides optional history, withdrawal/deletion and disable choices. The footer Privacy button is hidden. No first-visit banner or Reader Settings section is added.

Raw observations are retained for ninety days. Anonymous daily summaries, including mergeable cardinality sketches, are retained for 730 days. Minimal hashed visitor activity/first/last days supports cohort calculations beyond raw retention and expires after 366 idle days; local identity still rotates after twelve months. Losing browser storage prevents the reader from presenting an old ID for deletion. Identity changes/rotation also limit long-term cohort accuracy.

## Definitions and reports

All reporting dates use UTC. Data is unsampled, subject to browser blocking, loss and bot contamination. The private API exposes only named reports: Overview, Reach, Engagement, Audience, Content, Quality, Geography, Technology and paginated Visits. Bounds limit range to 730 days and result rows; there is no SQL text endpoint.

| Metric           | Meaning / limitation                                                                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Page view        | One accepted document ID, deduplicated across cumulative batches; reloads/new documents count again.                                                                                                   |
| Qualified read   | At least ten seconds of active foreground time.                                                                                                                                                        |
| Active duration  | Foreground, non-idle sampled time; not elapsed wall time or demonstrated comprehension.                                                                                                                |
| Impression       | 50% visibility for one second; includes a surface and result/card position.                                                                                                                            |
| On-site CTR      | Observed card/result clicks divided by qualified impressions. Rapid clicks may have no qualified impression; repeated clicks can yield more than 100%. This is not search-engine CTR.                  |
| Depth            | Maximum viewport geometry; not proof that skipped material was read.                                                                                                                                   |
| Retention        | Twenty progress buckets with at least one second of sampled dwell; revisions are separate. Curves require one content revision and ten qualified reads.                                                |
| Completion       | End visible plus dwell in at least sixteen of twenty buckets. End visibility alone is separate evidence.                                                                                               |
| Drop-off         | Last sampled bucket of an incomplete qualified read. Missing beacons can resemble abandonment; no exact psychological exit point is claimed.                                                           |
| Unique browser   | Opt-in identities only; never labeled as people or all visitors. Recent ranges use distinct raw hashes. Older ranges merge HLL p=10 sketches, about 3.25% standard error. Daily counts are not summed. |
| Returning rate   | Active opted-in browsers first seen before the range, or active on multiple days in it, divided by active opted-in browsers.                                                                           |
| Cohort retention | Exact-day returns at days 1, 7, 30, 90 and 180, grouped by first-observed month; immature windows or fewer than ten eligible browsers are insufficient.                                                |
| Consent coverage | Opted-in page views divided by all observed page views; not a survey of blocked readers.                                                                                                               |
| LCP / INP / CLS  | Supported browser observations, arithmetic means, counts and approximate p50/p75/p95 from bounded histogram summaries; not CrUX. CLS is transported scaled by 1000 and displayed as a score.           |
| Quality          | Accepted/rejected ingestion counters, supported failure categories, data freshness and observed D1 row reads/writes. Cloudflare billing remains authoritative.                                         |

Reach attributes impressions/clicks to stable target IDs across source pages. Target revision is not inferred from the card host's revision. Article audience subsets use retained raw observations, so they cannot reconstruct visits older than ninety days; their cohorts describe first site visits of those observed browsers. No account system means cross-device identity and true human counts are unavailable. External search-engine impressions, demographic profiles and Search Console integration are outside this iteration.

The local dashboard separates report connectivity from collection enabled/paused status and pending summary days. It supports date ranges, previous-period comparison, content/revision drilldown, hover charts with the actual dates of both comparison periods, keyboard-operable reset zoom, section dwell, source/device/campaign/language tables, cohorts and CSV exports. Empty or insufficient data remains explicit. CSV cells neutralize spreadsheet formula prefixes. Loading failures preserve the prior report and surface an error; review filters and freshness when inspecting a previous result.

## Storage, consistency and cost

Production report GETs read completed generations; they never trigger a full-day rebuild. Ingestion queues dirty days atomically. Five-minute maintenance resumes one leased work unit, processing at most 32 views or 12 event groups. Staged rows use a generation ID and a committed watermark publishes them only after every phase succeeds. Retry replaces staged totals instead of incrementing them. A failed commit leaves the previous report intact. Changes arriving during a generation leave the day queued for another pass.

Worker work units stay below the free per-invocation query bound, including metering and bounded cleanup. Views expire only after a committed summary covers their latest change and no dirty day remains. Cleanup is paged; it never removes unsummarized raw records. The older full-rebuild helper is for local maintenance/tests, not the deployed HTTP or cron path. Network-only reports skip legacy identity sketches and unnecessary retention payloads; large report ranges fail clearly rather than silently truncate.

D1 result metadata feeds service-local observed read/write counters, shown in Quality. Metering overhead is approximate and other account workloads are not included. The admission limits and page caps can pause or lag collection; charts must not hide these gaps. `GET /v1/status` and `POST /v1/maintenance` require the private report token. The first exposes protocol capabilities, optional-history mode, maintenance heartbeat, enabled/paused state, usage budgets, pending days and the captured site/origin/deployment ID; the second performs one bounded work unit. Neither exposes secrets or arbitrary SQL.

`GET /api/analytics-status` and `GET /api/services/readiness` remain private Studio APIs. Connections and `npm run services:check` distinguish verified read access, denied permissions, missing configuration and transport failures. Read access is not proof of write authorization or a successful deployment. Reports are stored privately under `.studio/reports/`.

The selected rollout is **free tier only**: no subscription upgrades, paid cache services or paid-plan assumptions. Free Workers currently allow 100,000 requests/day and 10 ms CPU per invocation; free D1 permits 50 queries per invocation, 5 million rows read/day, 100,000 written/day and 500 MB per database. Other applications share account limits. A saved URL or local latency measurement cannot prove actual cloud CPU, storage capacity or free-plan fit. Verify the cloud service and account usage before enabling readers; pause and report limitations rather than purchase capacity.

Validation uses synthetic events in actual local workerd/D1, plus browser visibility and storage tests. This establishes local behavior, not live Cloudflare delivery, production latency, actual traffic accuracy or a live bill. See [Cloudflare Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) and [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) before activating paid resources.

Audience metadata, Earth rendering, optional history, Search Console imports, protocol migration and service-health controls follow [audience foundations](audience-foundations.md). Deploy the collector before publishing version-2 clients. New migrations are additive; geography and histogram fields are never fabricated for older visits.

## Audience segments

Studio Analytics → **Filter audience** combines country, normalized device, browser, operating system, traffic source, campaign and language. Match any selected value within a dimension and every selected dimension together; each dimension accepts at most ten values. Use Apply filters, remove individual chips, or Clear filters. Country controls in the map and supported report-table cells update the same filters. Map point inspection remains separate. Date, content and revision filters still apply. Saved segments retain rules and a name, not a fixed date range; create/update/delete them in the filter toolbar. They are private, notebook/site-ID scoped, revision checked and excluded from portable notebook backups.

`src/shared/aca-segments.ts` owns the strict bounded `segment` JSON query and saved-segment vocabulary. Worker status advertises `segmentation-v1` without changing protocol 3 or reader batch version 2. `GET /v1/segment-options` supplies observed values; the local proxy uses `/api/analytics/segment-options`. `GET/PUT /api/analytics/segments` reads/writes `{value:{segments:[{id,name,siteId,filters}]},revision}` through private settings. Older collectors cannot silently ignore segment requests. All ordinary token/origin/no-store boundaries apply.

Migration `0004_segments.sql` adds an indexed generated joint key to existing coarse views, sparse `segment_daily`/`segment_events`, committed coverage and an independent event checkpoint. Joint views/retention/sections/audience/sketches share the ordinary day generation. Event work scans at most 32 indexed events and joins their parent views; cursor compare-and-set and count increments run in one D1 batch, preventing duplicate work after the parent state write fails. Keep the per-unit query budget and never construct all combinations of independent dimension counts. Production aggregate reports read only the complete committed generation; Visits retains its documented 90-day raw window.

Joint summaries survive for 730 days. Migration queues complete retained raw days; bounded maintenance also repairs missing joint generations after an older compatible Worker has run. Never rebuild a partially expired day from incomplete raw records. Older independent summaries cannot reconstruct intersections and remain unavailable. Responses carry applied `segment` and `coverage` (covered/observed days, missing days and available bounds). Missing history is not rendered as zero. Period comparison requires complete segment coverage in both periods; CSV exports include the actual snapshot's dates, rules and coverage.

Views, reading/retention, content, discovery events, geography, technology and observed performance support segments. Target-article impressions/clicks remain attributed to the source view's segment, with the existing target-revision limitation. Segment unique-browser counts merge opt-in HLL sketches and retain the approximate label; never sum daily uniques. Cohorts, returning-browser rates and daily network estimates are unavailable while segment filters are active. Quality's service request and D1 counters remain explicitly site-wide. No additional IPs, identifiers or reader text are collected.
