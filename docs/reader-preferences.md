# Reader preferences

`/settings/` is a generated, noindex utility page linked beside the navigation theme toggle. Home, Archive, Projects, Life and About remain the five public navigation destinations. Settings do not enter search, feeds or the sitemap.

The public page applies browser-local overrides to the author's presentation defaults. `ReaderPreferences` version 1 lives under `fieldnotes-reader-v1`; it accepts only bounded theme values, an independent 80–200% prose scale, and the site/none/local wallpaper choice. The existing appearance and transparency keys migrate on first use. Retain the legacy appearance key for Studio’s independent local choice. Resetting restores current site defaults rather than a copied preset. Preferences never write site configuration or call Studio APIs. Private previews ignore all reader overrides.

Pure `themeVariables` lives in shared `theme.ts`, without a React or server-renderer dependency. `appearance.js` is a separately bundled classic IIFE so it runs before the first paint, without an asynchronous module import. Only public theme defaults are embedded in `reader-defaults`. The normal client owns controls, cross-tab storage changes, system changes and BFCache refresh. `fieldnotes:reader-preferences` invalidates annotation line measurements and shared material geometry. Interface scale and prose scale remain independent. Prose scaling preserves the hierarchy of headings, paragraphs, code, tables and footnotes through the shared prose scale token.

`theme.wallpaperWash` accepts `auto`, `light` or `dark`. Studio Appearance owns the site default, with Automatic for existing notebooks. Automatic follows the resolved theme, including system changes and the navigation toggle; fixed washes remain independent of interface appearance. The reader's Background picture section can override the color and existing wash strength. A missing reader override inherits the current author default; resetting the section removes that override, including when the author default is a fixed wash. The choice applies to site and local pictures, survives reload and cross-tab updates, and is applied before paint. Reader changes never write author settings, and private previews use only the author's unsaved configuration. Wash opacity always uses the selected `--wallpaper-dim` directly, including zero; there is no `--protected-wash` variable or hidden minimum in any color/theme mode. Automatic contrast protection adjusts foregrounds and functional glass instead of changing picture wash or article tint. Utility labels receive quiet local glass tints; `.about-introduction` stays unframed and transparent on both About and Home, including with wallpaper. Static HTML includes the author wash and supporting tokens so no-JavaScript output follows the same default.

Pictures are decoded and oriented locally, bounded to 20 MiB / 40 million source pixels, and reduced to a 2400px longest edge. Encoding discards embedded metadata. The optimized binary is stored as an ArrayBuffer plus MIME type in IndexedDB, avoiding WebKit's Blob serialization failure; it is reconstructed into a local Blob URL when used. A small bounded raster thumbnail in preferences supplies the early background while the database loads. Pictures never enter the notebook, backups, Cloudflare or R2. Keep `blob:` permission limited to images in CSP. A failed preparation leaves the previous background intact; storage failure is visible.

Reader controls share native form semantics and range-fill enhancement. System reduced motion, reduced transparency and increased contrast retain priority. The live specimen uses a continuous glass reading surface and an intentionally denser code inset. Section resets and all-settings reset use the same quiet button treatment. Check desktop, tablet, 390px and 320px navigation geometry, keyboard controls, blocked storage, invalid pictures, reset, reload and cross-tab behavior in Chromium and WebKit.

Preserve zero through schema parsing, defaults and optical caches. Zero blur must not fall back to 11px. Square corners produce a valid displacement map. Ambient alpha scales through relative RGB where available, with a valid bounded color-mix fallback. Automatic contrast may strengthen functional glass, but never picture wash or article tint. Keep their requested strengths intact and show honest contrast estimates when transparent prose cannot meet the selected target.

The sticky desktop specimen has accessible Reading, Controls and Materials tabs with Arrow/Home/End navigation. Reading uses the existing Markdown pipeline for bilingual prose, hierarchy, lists, tasks, booktabs, quotation, inline/display MathJax SVG, captions and highlighted code. Compile the constant source once per process, isolate its TeX document, and omit client math/chart libraries. Controls demonstrate native input/search/select/range/checkbox/radio/switch/invalid/disabled/focus states without changing preferences. Materials shows the same floating navigation, linked glass card and continuous reading inset as the public site. Each scene retains its own scroll position. Phones use a compact 240px preview with explicit expansion to 65dvh. With JavaScript disabled the static Reading scene stays available.

Reading and Controls keep their decorative rim on the non-scrolling tab panel. Reading retains `glass-panel` on the inner article div for its regular tint, blur, border and reading styles; the outer frame hosts the stationary rim and the inner rim pseudo-element is suppressed. Controls use the outer glass material with an unframed inner form region. The inner labeled region owns scrolling, padding and content, with contained overscroll and a thin native scrollbar. Never attach a glass rim pseudo-element to scrolling content: it travels over the text. Keyboard focus outlines the fixed frame; individual form fields keep their native shared focus styles. Group demo fields responsively and retain the shared search icon treatment, validation and disabled states without writing reader preferences.

Settings styling is separately fingerprinted as optional `ReaderAssets.settingsStyle`; link it and the academic/content stylesheet only on the Settings route. Keep scene enhancement in the lazy Settings module. Older asset manifests remain accepted. Report the full Settings visit separately while keeping the existing initial reader budget.

## Author defaults and personal overrides

Studio Appearance owns every shared presentation default, including `theme.textScale` (80–200%, default 1) and `theme.focusMode` (default false). ReaderPreferences retains its existing top-level `textScale` and `focusMode` override keys; missing values inherit the current author default. Section/all resets delete overrides, including explicit false values, rather than writing a fixed preset. Prose size stays independent of interface scale and is present in static CSS. Focus is applied by the prepaint script on article pages; no-JavaScript output keeps normal navigation. Motion/transparency reductions also follow author-default → reader-override precedence; system accessibility preferences still take priority.

Article background tint retains the `readingOpacity` key and its 0–1 scale of the ordinary glass tint. Zero removes the article’s tint in both themes, independently of wallpaper, the functional glass floor or its legacy reading floor. Navigation/cards keep their own material. The generated article opacity uses the unprotected glass tint, including its existing dark-mode offset, multiplied by this strength. Do not reintroduce protected-reading variables or a minimum-reading-tint control. Contrast reports evaluate the actual article surface and may show insufficient contrast rather than secretly increasing its opacity.

## Text and contrast

Author `theme.contrast` and optional reader overrides share one pure resolver. Balanced and High Contrast presets provide heading/body/secondary/metadata/link/placeholder roles in both appearances. Reading and interface targets independently select 4.5:1 or 7:1. Balanced uses 7:1 reading and 4.5:1 interface; High Contrast uses 7:1 throughout. Advanced controls offer twelve bounded hex overrides and a functional glass tint floor. The legacy reading-floor field is retained for configuration round trips but is no longer exposed or applied.

Overrides merge per role. Reset contrast restores current author defaults. Reader-only null color overrides explicitly clear an inherited custom color when selecting a preset; deleting an override restores inheritance. Author configuration uses optional hex colors, without nulls.

Automatic protection evaluates the image luminance interval at the selected wash, strengthens functional glass, then adjusts foregrounds toward that appearance's ink. It never raises wash or article tint opacity. Requested colors remain separate from effective colors. A matching intermediate image luminance counts as insufficient even when endpoints appear acceptable. The guard is deterministic in static output and before paint, without image downloads or scroll-driven color changes. Manual mode preserves configured colors and shows advisory estimates. Estimates do not establish conformance for every painted pixel or arbitrary manual choices.

The preview includes bilingual prose, metadata, captions, links, placeholders, code and equations. System increased contrast retains strong ink and solid materials. Giscus CSS receives author foregrounds when generated; browser-local palettes apply to site-owned discussion controls.

Article typography defaults follow [article settings](article-settings.md). Resolve site plus optional article overrides before embedding `reader-defaults` and `ThemeStyle`; reader choices then apply with their existing precedence. Reset on an article restores its effective author defaults. Private previews ignore browser choices. Do not apply article-only CSS that overrides reader variables by specificity.

## Article focus and outline controls

Optional boolean `focusMode` remains in ReaderPreferences version 1. Omission inherits the author’s default `theme.focusMode`, which defaults off; explicit false overrides an enabled author default. The prepaint script applies the browser-local choice only through article-scoped CSS; public Settings itself retains its existing layout. The reader Page width control supports 720–1600px. Reader Settings exposes Focus mode and Reading reset clears it. Storage failure retains session behavior; cross-tab and BFCache refresh use the normal reader lifecycle. Studio previews ignore personal overrides and show the author’s focus default, with a temporary Exit focus action that does not write reader preferences. Without JavaScript, articles retain normal navigation.

Focus hides site header/footer, collection-back link, newsletter and related articles. It preserves article content, the compact article footer, annotation tools and the expanded desktop outline. Mobile keeps the collapsible bottom-left outline. An always-visible Exit focus action and Escape (when no input/dialog/popover owns it) restore the normal view. Focus uses the available page width while retaining its outline column and visible prose anchor. Missing outline configuration gets an article-header toggle.

Below progress, the outline exposes native Top/End links, previous/next heading controls and a pressed-state Focus toggle. Progress may be disabled without removing navigation or active-section tracking. The complete heading list stays available without a search field, including long articles. Reading progress covers the Markdown reading region instead of comments/recommendations, and ResizeObserver updates it after delayed media or typography changes. Heading links retain native fragments/history and reduced-motion-aware travel. Print hides these controls and uses [paper styling](printing.md).

## Footnotes and the right margin

Settings' page heading and action row span the same available width as the settings grid; only the introductory text has a reading-width limit.

All articles reserve a narrow right gutter beside the continuous reading panel, independently of the left outline. One always-visible 44px regular-glass rail places footnote numbers, existing discussion counts and the current-line annotation action. Its lower tools show the endnote count, link to the complete notes, and start keyboard annotation selection when available. A Collapse/Expand action folds the rail to a 44px handle without hiding article content. Fold state is local to the current page; desktop starts open and phone layouts start folded. Keyboard annotation selection opens the rail when needed. Footnote markers follow each reference's actual rendered line; repeated references keep their original number. Nearby overlapping markers use a grouped chooser, preserving separate endnote and discussion actions. Confirmed discussion counts and exact quoted-line identities remain unchanged, with no prose highlight.

The fold button keeps a 44px interaction target around a smaller glass face, with a directional chevron, quiet rim feedback and a visible keyboard focus ring. Reduced motion removes its movement. Folding dismisses the current-line annotation tooltip immediately; prose hover cannot show it again until the rail opens. If a breakpoint folds the rail while one of its tools has focus, focus returns to the fold button.

Hover or keyboard focus previews the already-rendered footnote locally. Clicking a margin marker pins the preview for following links; Escape or Close restores focus to its opener. Preview content retains formatted text and build-rendered mathematics, removes redundant backlinks and scopes cloned IDs and internal references. Embedded media is represented by its alternative text; the complete media remains at Read endnote, so a hover cannot trigger fresh media requests. No request or client Markdown renderer is needed, and Giscus can remain disabled. Native superscript links and endnotes remain the no-JavaScript fallback.

At 700px and below, the folded handle stays above the bottom-right Focus exit action. Footnote markers give way to the original inline references: activating one opens a bounded bottom sheet with a Read endnote link. Readers can expand the rail for its tools; annotation controls retain their keyboard/touch behavior. Focus mode preserves note tools. Print hides the rail/popovers and retains the endnotes. Positioning is shared with annotations, observes visible ranges and invalidates after font, media, resize and reading-preference changes. Retained focused markers are never briefly hidden during a positioning update.
