# Media usage in Studio

Media library cards show current-use and retained-reference counts plus a short list of actual titles. Searching includes file names and detailed titles, album names, setting fields and source paths. Existing All/In use/In history/Unused filters and cleanup protection remain available. Opening a card shows **Where this file is used**, with current uses visible and recovery references in a separate disclosure.

The private `GET /api/media/usage` audit retains its existing `active`, `history`, missing-file flags and graph revision. Optional `references`, `referenceCount` and `referencesTruncated` add display detail without weakening the complete cleanup graph. Each reference carries a stable display ID, current/history scope, source kind, title/context, canonical or private source path, optional field/Markdown body line, entry publication status, a Studio destination and an optional public route. Only current published entries get a public-route link. Draft/scheduled references stay in the local audit.

Show cover and sharing images independently, Markdown image/link/reference/HTML/directive locations, individual photos with album/caption, explicit album covers, About Markdown, and exact site settings fields such as wallpaper/portrait/favicon. Preserve parser-based exclusion of code examples and unused reference definitions. Markdown line numbers refer to the editor's body, excluding frontmatter. Retained details identify entry revisions, Trash, Photo Trash, collection Undo and About history; their private source paths and context explain why cleanup is blocked.

Current entry links open the matching Studio editor through the existing flush/navigation workflow. Other links open the relevant About/Photo journal/settings/Trash view; historical entries never invent a public URL. Media details keep the shared top-layer viewer and camera controls. Usage refreshes ignore superseded results, retain clear loading/error states and disable cleanup when the latest check is unavailable or history could not be parsed.

Detailed output is bounded to 300 locations per media file, with current references considered before history. Truncation is explicit; the existing complete `active`/`history` protection still determines deletion eligibility and stale-review detection. A capped list never makes a file unused. The audit and detailed paths are private Studio data, absent from public builds, feeds, search and media delivery manifests.

Missing files used by current content, including drafts and settings, appear in **Missing media references**. Files referenced exclusively by old recovery data do not appear in routine Media or Overview notices. Historical titles remain historical; an old sample revision is not presented as an image use in the renamed current article. Recovery records remain intact, and their full references still participate in private audits and cleanup protection. Restoring an old revision may require restoring its media.

The maintenance summary's `missing` count covers current references only; optional `missingRecovery` reports recovery-only files separately. Audit `missing` flags and the complete history graph remain unchanged, and retained references still block media cleanup. Viewing these notices never removes or rewrites revisions, Trash, backups or current content.
