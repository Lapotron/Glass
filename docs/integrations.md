# Optional integrations

Site settings → Integrations contains typed, default-off integrations. Existing notebooks need no migration. These fields hold public identifiers, never service credentials. The static blog, readable articles, RSS, and newsletter link remain usable without provider scripts.

## Discussions

Use [Giscus](https://giscus.app/) to select a public GitHub repository and Discussion category with the Giscus app installed. Copy its repository name, repository ID, and category ID into Studio. An individual entry can disable comments in Entry details.

The discussion uses its established `/blog/{slug}/` or `/lab/{slug}/` key with Giscus's specific mapping and strict matching. Configuring another public collection prefix keeps that key, as does changing the domain; changing a slug changes the discussion term. Keep established slugs stable or plan a provider-side migration. With load on request enabled, the external client loads only after Load discussion. Otherwise it loads when the section nears the viewport. Failures retain a direct link to GitHub Discussions and a retry action.

The engine generates complete, self-contained light/dark themes from `src/site/giscus-theme.css`: editor tabs and textarea, primary/secondary controls, comment headers and Markdown, reaction pills/popovers, thread replies, pagination, focus, disabled and reduced-motion/transparency states. The stylesheet targets Giscus's actual inner card, keeping replies on a continuous thread inset. It uses the site's atmosphere, accent, typography, radii and resolved contrast colors. There are no remote CSS imports. Fingerprinted `/assets/themes/<hash>/discussion-*.css` assets allow cross-origin loading; legacy `assets/discussion-light.css` and `discussion-dark.css` remain available. The frame receives the custom theme URL and theme updates through a message restricted to `https://giscus.app`. Article previews keep discussions disabled. See [Giscus advanced usage](https://github.com/giscus/giscus/blob/main/ADVANCED-USAGE.md) when changing its public API.

Follow site resolves theme assets against the active HTTPS origin, never the configured canonical URL. Check the asset's CSS content type and CORS header before using it. Localhost/HTTP and failed checks use the supported light/transparent-dark themes. Explicit provider themes bypass that lookup. This avoids broken styling when the canonical URL is a placeholder or a Pages preview uses a different origin.

Studio → Integrations → Preview discussion styles opens a sandboxed local specimen with Light/Dark controls. It renders the same generated CSS against representative Giscus markup using the current appearance draft. Sample editor/reaction interactions remain local; no GitHub script, login, comment, analytics or provider request runs. The token-protected `POST /api/integrations/giscus/theme-preview` validates `{theme,mode}` and returns HTML without writing content. Its sandbox and restrictive CSP isolate the example. This is the way to inspect custom styles on localhost; the real provider iframe requires publicly reachable HTTPS theme files after building and publishing.

Studio provides a token-protected `POST /api/integrations/giscus/check` with `{repo, repoId, categoryId}`. It makes a bounded, redirect-disabled read to Giscus's fixed category endpoint and returns `{status, repositoryId, categories, issues}`. Checks never save drafts or request credentials. Selecting a category fills the verified IDs. Import accepts only recognized public attributes from a Giscus script/web-component snippet; it never executes or stores arbitrary HTML, changes established mappings, or imports custom CSS URLs.

Defaulted comment options include language (`auto` follows the page), input position (`top`), metadata visibility (`true`), theme (`site`), heading and invitation. Preserve existing enabled/reactions/onDemand values. Article and section counts appear after their conversation loads. Line badges use the public annotation index described below; the editor still loads only on request. The optional About guestbook shares these provider settings.

Each host owns idle/loading/ready/empty/locked/unavailable states. A 15-second timeout exposes retry and the GitHub fallback. Late valid messages may recover a timed-out host. “Discussion not found” is the normal empty state; Giscus creates a discussion only after a reader contributes. Validate origin and exact iframe source for metadata/errors/resizes, and discard replaced-frame messages. Never retain or display viewer account metadata.

The pinned `giscus@1.6.0` component's message entrypoint needs an adapter guard because it otherwise applies every Giscus resize/error to every widget. Preserve its official OAuth/session behavior, allow a verified shared sign-out, and test isolated heights/status/counts when upgrading. Observers, message listeners and deadlines are cleaned up on retry or page disposal. A widget being attached is not evidence of readiness.

## Newsletter

Set an external HTTPS subscription page plus the invitation title, description, and button label. The generated footer invitation links to that page. This feature does not provision a mailing service, accept email addresses, or store subscribers. Subscriber consent and delivery remain with the selected service.

## Analytics

Studio → Site settings → Integrations has independent Cloudflare Web Analytics and Google Analytics 4 sections. Both default off and preserve each other's settings.

`site.integrations.googleAnalytics` defaults to `{enabled:false, measurementId:'', respectPrivacy:true, debugMode:false}`. The measurement ID is a public GA4 web-stream identifier beginning with `G-`, not a Google Tag Manager container, Ads ID, credential or executable snippet. IDs are trimmed/uppercased on preview/save. An enabled integration requires an ID. Find it in Google Analytics → Admin → Data streams → the web stream. Enable Debug mode temporarily to inspect events in GA4 DebugView; save and rebuild after changing any option.

The generated public configuration loads Google's async `gtag.js` from its fixed origin and queues its standard `js` and `config` commands. Each static document sends one automatic page view. Advertising features and personalization signals are disabled. An already-installed tag for the same stream owns its page view, avoiding a second manual configuration. The loader honors the standard `ga-disable-MEASUREMENT_ID` opt-out and, by default, Do Not Track / Global Privacy Control. Tracking is excluded from Studio, private previews, localhost, reader settings and missing-page responses. A configured ID is not proof that a real property has received data; verify your property with Google's tools after publication. See [Google tag setup](https://developers.google.com/tag-platform/gtagjs), [privacy parameters](https://developers.google.com/tag-platform/security/guides/privacy) and [GA CSP requirements](https://developers.google.com/tag-platform/security/guides/csp).

Google's script and collection origins enter CSP only when GA4 is enabled. Initialization lives in the compiled reader script, without enabling inline scripts or unsafe evaluation. No tracking initialization or provider configuration is emitted in private preview documents. Controlled browser tests intercept provider traffic; they must never send real analytics hits.

Cloudflare Web Analytics has an explicit installation mode under **Beacon installation**. Missing `site.integrations.analytics.mode` defaults to `manual`, preserving existing notebooks; the integration still defaults off. With `enabled:true` and `mode:'managed'`, Cloudflare supplies its automatic beacon and Studio emits only the matching CSP permissions. No public token or second loader is required. Cloudflare owns injection, privacy behavior and page exclusions in this mode; configure those in its dashboard. Turning this setting off removes its CSP permissions but does not turn off an independently enabled Cloudflare injection setting.

With `mode:'manual'`, enabling requires the public 32-character beacon token. The client adds the documented module beacon with static-page tracking (`spa: false`), unless a standard or versioned Cloudflare beacon is already present. It skips localhost, Studio previews, and, by default, Do Not Track or Global Privacy Control signals. Select Cloudflare automatic injection when Pages or your zone already supplies the snippet. See [Cloudflare setup](https://developers.cloudflare.com/web-analytics/get-started/) and [its CSP requirements](https://developers.cloudflare.com/web-analytics/faq/#what-do-i-need-to-add-to-my-content-security-policy-csp).

`src/shared/security.ts` supplies the production CSP. Giscus script/frame/connect origins and Cloudflare script/connect origins appear only when their corresponding integration is enabled. Both generated Pages headers and the local static server use this policy. Media has a separate sandbox policy. Do not weaken the global policy to accommodate arbitrary embed snippets.

Implementation paths: `src/console/IntegrationSettings.tsx`, `src/site/integrations.ts`, `src/engine/integrations.ts`, shared contracts/security, and `src/site/pages.tsx`. Tests with stubbed providers verify the contract without claiming a real service connection.

## Inline section conversations

Explicit discussion directives can opt into an inline reader thread. Use the locally bundled official `giscus` web component, loaded only after the section is opened. Each component owns its own iframe. The old global client script targets the first `.giscus` container and must not be reused for multiple threads.

Existing article threads keep their canonical-path mapping. New section mappings are `entry/{stableEntryId}/section/{stableKey}`, independent of heading/title/slug changes. Preserve strict matching and provider theme updates, and scope messages to the correct iframe. All provider activity remains disabled in Studio previews and for entries with comments disabled. Provider configuration does not provision a GitHub repository or establish a live connection.

## Line annotations

With article comments enabled, hovering a rendered text line reveals Annotate this line at the right border. Show the action without highlighting or tinting the article text. Clicking opens a quoted note and its replies in a nonmodal glass popover, or a bottom sheet on phones. Annotate a line in the article header provides keyboard entry; Up/Down selects a line, Enter opens it, and Escape closes it with focus returned. Scroll the selected passage into view before focusing its action. Touch readers can tap a passage and then its edge action, which remains available after touch release. Keep the selected passage fixed while its note is open. Hovering and selecting never contact Giscus.

Lines with confirmed discussions retain a small glass badge without hover. The badge stays at the first visual line of its original quoted range, follows scrolling, rewrapping and reader preferences, and opens the existing discussion by its verified number. It displays comments plus replies; an ellipsis means the count is unavailable, and a `+` indicates a known subtotal. Never turn missing metadata into zero. Its accessible name distinguishes comments/replies, and closing the popover returns focus to the badge. If several original ranges now start on one visual line, group their badge and counts and offer an Annotations on this line selector inside the popover. Keep every original mapping and quote intact. Hidden and outdated passages receive no misplaced badge; the Annotations tabs retain their original-thread links. Position only visible badges and keep prose unhighlighted. The hover action remains available for unannotated lines and keyboard line selection.

The selected range is the exact visual line, including text across emphasis and inline code. Client indexing uses the public rendered text only. Math is an atomic accessible expression and code lines retain indentation. The mapping is `entry/{stableEntryId}/line/{blockKey}/{start}-{end}` and the permalink is `#line-{blockKey}-{start}-{end}`. A block key is the first 20 hex characters of SHA-256 over its kind and rendered text, plus its duplicate occurrence. Offsets are UTF-16 positions within that public text, never private Markdown source positions. Keep source-range preview attributes out of published pages.

A shared permalink reopens its original quote after responsive rewrapping or unrelated content insertion. Changing the anchored block produces a visible outdated-line message and a GitHub search link, rather than attaching the note to different text. Repeated identical blocks are distinguished by occurrence; inserting another identical block before one can change that distinction. Browse annotations opens a native GitHub title search scoped to the entry. Do not claim unread counts.

Each line owns an isolated Giscus frame using the existing provider settings and strict matching. The first contribution creates the discussion through Giscus; authentication, replies, reactions and moderation stay with GitHub. A pinned SDK adapter supplies the supported iframe `description` and `backLink` parameters per instance so the discussion contains its quote and permalink without changing global page metadata. Retain the line fragment after the SDK consumes an OAuth callback, without restoring its consumed query parameter. Recheck this adapter and the iframe message guard when upgrading Giscus.

Closing retains the current provider frame and draft; selecting another line replaces and cleans up that frame. Line counts, errors and heights never affect the main article or another section. Disabled entries and private previews expose no line runtime or provider activity. Test quoted ranges across formatting, responsive permalinks, outdated source, keyboard/touch access, frame isolation, retry and callback restoration with controlled provider responses; never create real comments during verification.

The floating left sidebar has Outline and Annotations tabs. The end-of-article panel has Discussion and Annotations tabs. Both annotation views share one registry and display the same notes, sorted by passage with quotes, section context and visual line positions. Line numbers reflect the current viewport; permalinks retain the original quoted range. Notes in hidden rich Markdown tabs reveal their panel when opened. Changed passages remain identifiable and link to the original GitHub thread. Tab controls use arrow keys/Home/End, preserve their own selected view, and fold the compact outline after a note is selected.

Existing notes are discovered from GitHub's public, filtered, paginated Discussions Atom feed, not from Giscus's single-thread lookup. `GET /api/annotations/{publishedEntryId}?page=1` is a narrow read-only adapter shared by local Studio serving and Pages. It fixes the repository to the saved public configuration, allows published comment-enabled entry IDs only, validates thread terms and GitHub URLs, and returns plain text metadata. Filter by the stable article/line title prefix across repository categories: category filters redirect GitHub feeds to HTML. Existing indexed notes open by their validated discussion number, retaining access across category changes; new notes use the configured Giscus category and established line term. The adapter omits identity/session fields, never forwards credentials, and rejects writes, arbitrary URLs, redirects, invalid pages, invalid feeds, bodies over 2 MiB and reads over 10 seconds. Successful reads are cached for 60 seconds; failures permit retry.

The article discovers the shared index in the background so existing badges appear without opening a tab or Giscus frame. It follows 25-entry pages up to page 100, yields between pages and pauses further background requests while the document is hidden. Either tab reuses these records; Refresh and Load more remain available, and a `+` tab badge indicates that pages remain. Confirmed Giscus metadata updates the badges and both views after contributions; an unsubmitted empty form is not an existing note. Refresh failures retain known records and expose retry/native GitHub navigation. Hover does not initiate provider requests. Private previews and comment-disabled articles run neither discovery nor Giscus.

The read adapter enriches validated feed threads with anonymous GET requests to Giscus's [discussion metadata endpoint](https://github.com/giscus/giscus/blob/main/pages/api/discussions/index.ts), fixed to the saved repository and discovered discussion number. It requests the first 100 comments to obtain reply totals when that covers the entire thread; paginated subtotals are not presented as complete. Widget updates likewise omit an uncertain reply subtotal for conversations beyond its initial 30-comment front/back pages. Count reads use four bounded workers, a shared four-second deadline, a 512 KiB body limit, manual redirects and a 60-second metadata cache. Responses expose only validated counts, never viewer identities, session data or comment HTML. Failed/blocked count reads preserve the note with an unknown count. The existing feed read retains its separate ten-second/2 MiB bound; the browser permits sixteen seconds for the combined read. No reader credential or extra secret is required.

With discussions enabled, the builder packages `_worker.js`, a narrowly scoped `_routes.json`, and `assets/annotation-config.json`. The worker serves only this read endpoint; other requests delegate to Pages ASSETS. Public documents stay generated HTML. The configuration contains only the public repo/category and eligible published IDs. No token, database or additional binding is required. Disabled builds omit these files. Preserve the fixed route boundary and static CSP behavior when changing publication; see [publishing](publishing.md).

Per-article conversation, authored discussion blocks and line annotations can be independently disabled under optional `discussion` frontmatter; legacy `comments` remains the master switch. See [article settings](article-settings.md). Both local and built annotation allowlists require effective annotation enablement. Annotation-only conversation panels start on Annotations; all-off output has no conversation controls.

## Custom discussion themes and ACA

The maintained Giscus color/editor/frame styling and fingerprinted theme asset contract are documented in [reader upgrades](reader-upgrades.md#giscus). Custom CSS is self-contained and resolved from actual light/dark contrast tokens. Keep built-in fallback themes, runtime updates, independent frames and established annotation mappings.

[Advanced Customized Analytics](aca.md) is independently deployed and default-off. Its configuration belongs to `site.integrations.aca`; only public endpoint, site ID and collection preferences enter reader output. The private report token belongs to Studio Connections, and its identity secret belongs to the Worker. Reader Settings owns explicit anonymous/opt-in/off choices and forgetting status. Do not replace existing CF/GA choices, invent historic metrics, store search queries or treat opted-in browsers as all visitors.
